# 프로젝트 개발 오버라이드

Acorn 공통 규칙과 설치된 Skill에 없는 프로젝트 전용 차이만 기록한다.

기본 기준:

- `acorn/skills/coding-standards/SKILL.md` (최소 변경 정책 포함)
- 작업에 맞는 `acorn/skills/*/SKILL.md`
- 저장소의 기존 구조와 관례

규칙:

- 이 문서의 프로젝트 전용 규칙이 공통 기준보다 우선한다.
- 공통 코딩 규칙을 중복해서 복사하지 않는다.
- 실제 사용하는 스택, 라우터, 패키지, 구조 제약만 기록한다.
- 더 이상 유효하지 않은 오버라이드는 제거한다.

## UI/UX 제약 조건

- 모든 화면과 주요 콘텐츠 영역은 세로 스크롤만 사용한다. 가로 스크롤을 필요로 하는 UI(가로 캐러셀, 가로 스와이프 목록, 수평 스크롤 탭 등)는 도입하지 않는다.
- 모바일과 데스크톱 모두에서 콘텐츠가 화면 너비를 넘어 가로 오버플로를 유발하지 않도록 반응형으로 배치한다.
- 항목이 많거나 폭이 부족하면 가로로 넘기지 말고 줄바꿈, 세로 쌓기 또는 레이아웃 재배치로 해결한다.
- 이 규칙은 신규 개발과 기존 화면 수정 모두에 적용한다. 단, 이번 규칙 추가 자체가 기존 UI의 일괄 수정을 뜻하지는 않는다.

## 반응형 레이아웃 제약 조건

- 모바일 우선(Mobile-first)으로 디자인하고 구현한다.
- 태블릿과 데스크톱 등 넓은 화면에서는 콘텐츠를 좁은 모바일 너비로 고정하거나 중앙에 작은 앱 화면처럼 가두지 않는다. 사용 가능한 화면 너비를 자연스럽게 활용한다.
- 태블릿 화면도 실용적인 수준으로 반응형 배치를 지원한다. 화면 너비에 따라 간격, 열 수, 카드/폼/지도 배치 등을 유연하게 조정한다.
- 넓은 화면에서 모든 콘텐츠를 무조건 늘어뜨릴 필요는 없다. 읽기 좋은 개별 텍스트 영역의 너비는 제한할 수 있지만, 페이지 전체 레이아웃은 넓은 화면에 적응해야 한다.
- 모바일에서는 한 열 중심, 넓은 화면에서는 필요에 따라 다열 배치를 사용하되 앞서 정한 가로 스크롤 금지 규칙을 준수한다.
- 이번 규칙 추가는 기존 화면의 즉시 일괄 수정을 의미하지 않는다.

## 모달 depth 및 화면 전환

- 상세·등록·확인 등 모달 흐름은 Drawer 기반 depth stack으로 구성한다.
- 모바일에서는 각 depth 화면이 뷰포트를 전부 덮어 배경 화면에 시선이 분산되지 않게 한다.
- 1차 화면은 아래에서 위로, 2차 화면은 오른쪽에서 왼쪽으로, 3차 화면은 왼쪽에서 오른쪽으로 진입시킨다.
- depth 화면에는 뒤로 가기 버튼을 두지 않는다. 닫기 동작은 쌓인 화면을 모두 닫고 원래 화면으로 돌아간다.
- Drawer의 주요 실행 버튼은 하단 safe area에 고정하고, 높이와 Olive 색상을 일관되게 맞춘다. 나란히 선택하는 주요 버튼도 같은 색상을 쓴다.
- 단계 완료로 현재 입력 화면이 닫히는 동작은 허용한다. 사용자가 이전 depth로 이동하는 별도 탐색 동작은 제공하지 않는다.
- 애니메이션은 `prefers-reduced-motion` 설정을 따른다.
- 이 규칙 추가만으로 기존 화면을 일괄 변경하지 않는다. 화면별 수정 요청이 있을 때 적용한다.

## UI 스타일 및 컴포넌트

- UI는 기존 shadcn 컴포넌트와 Tailwind 유틸리티를 우선 사용한다. 같은 인터랙션을 직접 다시 만들지 않는다.
- 애니메이션이 필요한 UI는 Animate UI 컴포넌트를 우선 검토하고, 필요한 컴포넌트만 적용한다. Animate UI는 shadcn처럼 소스 코드를 프로젝트에 추가해 조정하는 방식으로 사용한다.
- `@animate-ui/cli animate all`은 전체 shadcn 컴포넌트를 변경하므로 기본 작업 흐름으로 사용하지 않는다. 화면 작업 범위에 포함된 컴포넌트만 CLI 또는 수동으로 적용한다.
- Animate UI 컴포넌트를 찾거나 추가할 때 `components.json`의 `@animate-ui` 레지스트리와 shadcn MCP를 사용한다. MCP에서 필요한 컴포넌트를 골라 추가하고, 기존 컴포넌트를 바꾸는 작업은 해당 컴포넌트 범위로 제한한다.
- 새 UI 아이콘은 Lordicon의 무료 아이콘을 우선 사용한다. 무료 라이선스에 맞게 Lordicon 출처 링크를 앱 푸터에 표시하고, PRO 표시 아이콘은 사용하지 않는다.
- 기존 아이콘을 이 규칙만으로 일괄 교체하지 않는다.
- 컴포넌트 전용 스타일을 `globals.css`나 여러 스타일 파일에 나눠 추가하지 않는다.
- Tailwind나 기존 컴포넌트로 표현하기 어려운 스타일만 custom CSS로 작성하고, 해당 기능이 소유한 한 곳의 스타일 파일에 둔다.
- 반복되는 UI 동작과 레이아웃은 기존 shadcn 컴포넌트를 확장하거나 재사용 컴포넌트로 묶는다.
- 이 규칙 추가만으로 기존 화면을 일괄 변경하지 않는다.

## 브랜드 컬러 제약 조건

- 기본 시그니처 팔레트는 **Olive / Sage(Khaki 계열) / Cream(Beige 계열)** 세 가지다. 먹스토리 화면의 `src/app/story/story.css`에 선언된 색상 토큰을 기준으로 한다.
  - **Olive** `#4D5B3C` (`--ink`): 주요 텍스트, 강조, 활성 UI.
  - **Sage / Khaki** `#D9D8B8` (`--sage`): 보조 배경, 표면, 차분한 강조.
  - **Cream / Beige** `#EFE6D4` (`--cream`): 기본 배경, 밝은 표면, 어두운 강조색 위 텍스트.
- 신규 UI와 기존 UI를 수정할 때 이 세 색을 기본 시각 언어로 사용한다. 임의의 신규 대표 색상이나 별도 팔레트를 도입하지 않는다.
- 경계선·보조 텍스트·상태 표현에 필요한 파생 색과 의미 색상은 사용 가능하되, 세 가지 기본색을 대체하지 않고 대비와 가독성을 확보한다.
- 색상값을 화면마다 새로 추측해 지정하지 말고 기존 시그니처 토큰을 참조한다.
- **공통 토큰화 원칙:** 현재 `story.css`에만 정의된 세 기본색은 다음 디자인 시스템 정리 시 `src/app/globals.css` 등 앱 전체에서 접근 가능한 단일 토큰 소스로 옮긴다. 컴포넌트는 공통 의미 토큰을 사용하고, 페이지별 HEX 하드코딩이나 중복 정의를 늘리지 않는다. 기존 화면 전체 변경은 별도 작업으로 진행한다.
- **추가 색상 정책:** 네 번째 브랜드 컬러는 도입하지 않는다. 필요하면 Olive의 농도 차이, 중립적인 경계선/텍스트 색과 상태별 의미 색상만 제한적으로 허용한다.
- **확정된 보조 상태 색상:** 오류/삭제 **Muted Brick** `#B4534B`, 경고 **Muted Amber** `#A47536`, 성공/완료 **Muted Green** `#527A60`. 기본 브랜드 색상 3종과 구분해 상태 표시 목적으로만 사용한다.
- 버튼, 알림, 태그 등에서 해당 상태 색상이 필요하면 지정된 HEX를 의미 토큰으로 재사용하며 임의의 대체 빨강·노랑·초록을 추가하지 않는다. 상태를 색상에만 의존하지 않도록 텍스트/아이콘을 함께 사용하고 실제 배경 대비를 검증한다.
- 이번 변경은 규칙 문서만 수정하며 기존 화면의 색상을 일괄 변경하지 않는다.
